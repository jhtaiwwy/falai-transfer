三端原生，不是三套壳。

安卓、鸿蒙、Windows 各自用本平台的原生技术栈写，共享同一份协议。所以传输速度是平台能给到的上限，不是 WebView 的上限。

Android

Kotlin · Jetpack Compose

折叠屏展开合拢不重建 Activity，传输不中断。前台 Service + WakeLock，锁屏照传。手机三 Tab、展开态 NavigationRail、平板三列网格。

HarmonyOS

ArkTS · ArkUI

用 @kit.NetworkKit 做 UDP 发现，photoAccessHelper 直接落相册，文档走 DocumentViewPicker 进公共下载目录。免权限，不弹多余授权。

Windows

Tauri · Rust · React

发现与 TCP 服务跑在 Rust 侧，不经过 JS 桥。安装包十几 MB，不是动辄上百兆的 Electron。托盘常驻，随开随收。

传一个 8GB 的视频，中途去接个电话。

这些不是待办清单，是已经跑在真机上的行为。

断点续传

用 transferId 标识批次，接收端返回每个文件已收的 offset。重发同一批次，已完成的跳过，未完成的从断点接着写。

暂停与继续

暂停即停止推流但保持连接，两端进度冻结、速度归零。继续后从那个字节接着发，不用重来。

白名单免确认

自己家里的设备加进白名单，以后发过去直接落盘，不弹窗。陌生设备仍然要你点一下「接受」。

网络容错

接收端口被占用就从 47801 自动往后挪，实际端口靠广播告诉对方。WiFi 断了立刻判失败并提示，临时文件留着等你续。

日志可查可删

每次传输的时间、方向、对方、文件名、大小、耗时、均速都落本地。左滑删单条，一键清空，不上传任何地方。

多屏自适应

按窗口宽度分档：手机底部三 Tab、折叠展开和横屏走左侧 NavigationRail 两列、平板三列限宽居中。

广播能过，
握手过不去。

2026-10-18 · 酒店 WiFi · 一次失败的真机联调

在酒店 WiFi 上试的时候，界面明明列着对方设备，点发送却停在 0/12，二十一秒后弹出 os error 10060。

查下去发现：对方每 2 秒的 UDP 广播持续正常到达，但 ARP 表里对方 MAC 全是 0，ping 不通，TCP 47801 超时。广播是二层泛洪，能过；ARP 应答和 TCP SYN 是单播，被 AP 扔了。

这就是路由器上的客户端隔离。代码一行都改不了，换成手机热点，一次通。
