# 局域网文件互传 App（安卓版 + 鸿蒙版）技术方案

> 版本：v1.1 | 日期：2026-07-20 | 状态：安卓版开发中
> v1.1 变更：新增暂停/继续（断点续传）、文件预览、网络切换容错（端口占用自动切换 / WiFi 断开自动失败）、多屏比例自适应布局、后台继续传输；协议升级到支持 `transferId` 与 `offset`。

## 1. 目标与约束

开发一个照片/视频/文件互传应用，分**安卓版**（Kotlin + Jetpack Compose）和**鸿蒙版**（ArkTS + ArkUI）两个独立 App，两端可互相传输。

硬性要求：

1. 基于局域网直连，无第三方服务器，无需互联网
2. 支持安卓、鸿蒙两个系统互传
3. 传输实时进度显示
4. 实时速度显示
5. 界面简洁美观
6. 可查看传输日志，可删除日志
7. 通信方式由方案决定（本文档选定 WiFi，见第 2 节）

## 2. 通信方式选型

| 方案 | 速率 | 结论 |
|---|---|---|
| 蓝牙（经典/BLE） | 0.2~3 MB/s | ❌ 排除：传视频/批量照片太慢，配对流程繁琐，鸿蒙蓝牙 API 限制多 |
| WiFi 局域网 TCP | 20~80 MB/s（视路由器） | ✅ **选定**：速率够、两端 socket API 都成熟、无需配对 |
| WiFi Direct（P2P 直连） | 高 | ❌ 排除：安卓/鸿蒙 P2P API 差异大，跨系统协商兼容性风险高 |

**最终方案：WiFi 局域网，UDP 广播自动发现 + TCP 直连传输。**

- 前提：两台设备连同一个 WiFi（同一局域网）
- 无路由器场景（户外）：二期可加"热点模式"——一方开热点另一方接入，即构成局域网，传输协议不变。一期先不做

## 3. 整体架构

两端代码独立（Kotlin / ArkTS 无法共用 UI 与平台 API），但**通信协议完全一致**，协议是两端互传的契约：

```
┌─────────────┐   UDP 广播发现（端口 47800）   ┌─────────────┐
│   安卓版     │ ◄──────────────────────────► │   鸿蒙版     │
│ Kotlin+Compose│                              │ ArkTS+ArkUI │
│              │   TCP 直传（端口 47801）      │              │
│              │ ◄══════════════════════════► │              │
└─────────────┘   JSON 头 + 原始字节流         └─────────────┘
```

每端内部模块（两端结构对称）：

| 模块 | 职责 |
|---|---|
| DiscoveryService | UDP 广播自身信息 + 监听局域网内其他设备，维护在线设备列表 |
| TransferServer | 常驻 TCP 服务，接收对方发来的文件，写入相册/文件系统 |
| TransferClient | 向对方发起传输，流式读取本地文件发送 |
| 文件模块 | 调系统选择器选照片/视频/文件；接收后存入相册或下载目录 |
| 日志模块 | 本地记录每次传输（SQLite/JSON），提供查询、单条删除、清空 |
| UI 层 | 首页（设备列表+收发）、传输页（进度+速度）、日志页 |

## 4. 通信协议设计

### 4.1 设备发现（UDP 广播，端口 47800）

每 2 秒广播一次自身信息（JSON）：

```json
{ "app": "FT", "name": "vivo X Fold 3", "os": "android", "tcpPort": 47801, "version": 1 }
```

收到他端广播即加入在线设备列表（超过 6 秒无心跳标记离线）。手动输入 IP 作为兜底（应对路由器开启 AP 隔离导致广播不通的场景）。

### 4.2 文件传输（TCP，默认端口 47801，占用时自动后移）

接收方监听端口从 47801 起依次尝试绑定（47801~47811），实际绑定端口通过 UDP 广播的 `tcpPort` 字段告知对端，因此端口冲突对发送方透明。

流程（v1.1，支持断点续传）：

```
发送方                                    接收方
  │ ── ① 连接，发请求头 ──────────────────► │
  │    [4字节头长][JSON: {transferId, files:[{name,size}], total, from}]
  │ ◄── ② {status: ACCEPT, offsets:[...]}   │ 白名单自动接受 / 弹窗确认
  │        或 {status: REJECT}              │ offsets = 各文件已接收字节数
  │ ── ③ 逐文件: [4字节元信息长][JSON{name,size,offset}]
  │ ── ④ 原始字节流（32KB 块流式读写，─────► │ 先写临时文件 *.part，
  │        从 offset 处续传）                │ 收满后导入相册/下载目录
  │ ◄── ⑤ 单文件 ACK ────────────────────── │
  │ ◄── ⑥ 全部完成 DONE ─────────────────── │ 清理会话临时文件
```

设计要点：

- **流式读写**：不分块缓存整个文件，内存占用恒定，GB 级视频无压力
- **接收方确认**：收到请求弹窗显示"XXX 想发给你 N 个文件（共 xx MB）"，接受/拒绝；白名单设备免确认自动接收
- **暂停/继续**：发送端暂停即停止推流（连接保持），双方进度冻结、速度归零；继续后从断点字节接着发。接收端数据读取超时 5 分钟，超时断开会话
- **断点续传**：`transferId` 标识一批次传输。接收方先把数据写入 `cacheDir/incoming/<transferId>_<序号>.part`，收满才导入相册/下载目录；会话中断后临时文件保留。发送方重发同一批次时携带相同 `transferId`，接收方在 ② 中返回各文件 `offsets`，发送方跳过已完成文件、从 offset 续传未完成文件；临时文件超过 24 小时自动清理
- **网络切换容错**：监听系统网络回调，WiFi 断开/切换时立即终止进行中的传输并提示"网络已断开"，临时文件保留可续传；设备列表即时清空
- **进度**：双方各自统计已传字节 / 总字节，UI 每 200ms 刷新
- **速度**：1 秒滑动窗口计算（bytes/sec），格式化为 KB/s、MB/s
- 加密：一期不做，协议预留 `version` 字段可扩展

## 5. 功能清单（一期）

| # | 功能 | 说明 |
|---|---|---|
| 1 | 设备发现 | 自动列出同局域网设备，支持手动输 IP |
| 2 | 发送 | 选照片/视频/文件（**多文件批量选择**）→ 预览确认 → 选设备 → 对方确认 → 传输 |
| 3 | 接收 | 弹窗确认（白名单免确认）→ 存入相册（照片/视频）或下载目录（其他文件） |
| 4 | 进度 | 总进度条 + 当前文件名 + 已传/总量 |
| 5 | 速度 | 实时速度 + 平均速度 + 预计剩余时间 |
| 6 | 日志 | 列表展示（时间、方向、对方设备、文件名、大小、结果、耗时、均速）；支持左滑删单条、一键清空；本地持久化 |
| 7 | 界面 | 简洁卡片风，安卓 Material 3 / 鸿蒙 ArkUI 原生风格，浅色主题；多屏比例自适应（见 5.1） |
| 8 | 暂停/继续 | 发送端可暂停并继续；传输中断后重发同一批次自动断点续传（协议 `transferId` + `offset`） |
| 9 | 文件预览 | 发送前预览所选文件（缩略图/名称/大小，可移除单个）；接收完成后可直接打开预览（调系统查看器） |
| 10 | 网络容错 | 端口被占用时接收端口自动后移（47801~47811）；WiFi 断开/切换立即判失败并提示，临时文件保留可续传 |
| 11 | 后台传输 | 传输期间前台 Service + WakeLock，切后台/锁屏不中断，通知栏显示传输中 |

### 5.1 多屏比例自适应矩阵

按**宽度尺寸档位**（WindowSizeClass）自适应，折叠态/展开态天然覆盖，无需厂商私有 API：

| 设备（形态） | 宽度档 | 布局形态 |
|---|---|---|
| 安卓直板机（含 Mate 80 Pro 安装的安卓壳场景）、Pura X / Pura X Max / vivo X Fold 3 Pro **折叠态** | Compact | 底部三 Tab 导航 + 单列卡片流（当前布局） |
| vivo X Fold 3 Pro **展开态**、Pura X / Pura X Max **展开态**、Mate 80 Pro 横屏 | Medium | 左侧 NavigationRail + 内容区两列网格（设备/日志卡片双列） |
| MatePad Air 12（平板，横竖屏） | Expanded | NavigationRail + 内容限宽居中 + 三列网格 |

交互方式不变（点选/弹窗/左滑删除），仅布局密度与导航位置随宽度切换；`configChanges` 声明保证折叠展开切换不重启 Activity、传输不中断。

```

┌─────────┬─────────┬─────────┐
│  传输    │  日志    │  我的   │

```

## 7. 关键技术点（分端）

**安卓版**（目标机：vivo X Fold 3，Android 14）
- 发现：`DatagramSocket` 广播 + `WifiManager.MulticastLock`
- 文件选择：系统 Photo Picker + SAF，免存储权限
- 保存：先写 `cacheDir/incoming/*.part` 临时文件（支撑断点续传），收满后导入 `MediaStore`（照片/视频）或 `Download/发来`
- 权限：`INTERNET`、`ACCESS_WIFI_STATE`、`NEARBY_WIFI_DEVICES`（Android 13+）、`POST_NOTIFICATIONS`、`FOREGROUND_SERVICE_DATA_SYNC`
- 后台：传输期间前台 Service（dataSync 类型）+ `PARTIAL_WAKE_LOCK`，切后台/锁屏不中断；`configChanges` 声明折叠/展开、旋转不重建 Activity
- 容错：`ConnectivityManager.NetworkCallback` 监听网络断开；接收端口 47801~47811 自动后移
- 自适应：`material3-window-size-class` 按宽度档切换 NavigationBar / NavigationRail 与网格列数；缩略图用 Coil

**鸿蒙版**
- 发现：`@kit.NetworkKit` 的 UDP socket
- 文件选择：`photoViewPicker` / `documentViewPicker`，免权限
- 保存：`photoAccessHelper` 存相册；其他文件用 `DocumentViewPicker` DOWNLOAD 模式直达公共「下载」目录 `Download/<包名>/`（不弹界面、免权限）。**坑**：拿到的 `file://docs/...` uri 不能直接 `fs.openSync(uri, CREATE)`（真机报 `13900002`），必须先 `new fileUri.FileUri(uri).path` 转成真实路径再创建写入（见[官方 save-user-file 文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/save-user-file)）；失败时回退应用私有目录 `filesDir/Download/`
- 权限：`ohos.permission.INTERNET`、`ohos.permission.GET_WIFI_INFO`、`ohos.permission.WRITE_IMAGEVIDEO`（接收图片/视频落相册用，启动时运行时申请）
- 构建：DevEco Studio + hvigor（**本机尚未安装，需先装**）
