# 鸿蒙应用发布指南（发来 App 上架华为应用市场）

> 适用项目：`harmonyos/`（bundleName：`com.falai.transfer`，versionName：1.0）
> 目标：上架华为应用市场（AppGallery）。个人开发者可免费上架。
> 整理时间：2026-07

---

## 0. 总览与时间预估

| 阶段 | 事项 | 预估耗时 | 能否并行 |
|---|---|---|---|
| 1 | 华为开发者账号注册 + 实名认证 | 1~2 天 | 可 |
| 2 | APP 备案（工信部） | 1~3 周 | 可，**最先启动** |
| 3 | 软件著作权登记 | 约 15 个工作日 | 可，**最先启动** |
| 4 | 发布签名 + release 出包 | 半天 | 等 AGC 创建应用后 |
| 5 | AGC 填资料 + 提交审核 | 审核 1~3 个工作日 | 等以上全部 |

**关键结论**：技术工作（阶段 4、5 的材料）很快就能做完，瓶颈在备案和软著，应第一天就启动。

---

## 1. 开发者账号

1. 打开华为开发者联盟：https://developer.huawei.com/consumer/cn/
2. 注册账号 → 完成**实名认证**（个人开发者用身份证，免费；企业用营业执照）。
3. 实名认证通过后，进入 **AppGallery Connect（AGC）**：https://developer.huawei.com/consumer/cn/service/josp/agc/index.html

---

## 2. APP 备案（工信部，硬性要求）

没有备案号，华为应用市场（及国内所有应用市场）不予上架。

- 官方指引：[APP核准（APP备案）指引 - 华为开发者官网](https://developer.huawei.com/consumer/cn/doc/app/50130)
- 办理入口：通过接入商办理，推荐**华为云备案系统**（与 AGC 同账号体系，最顺）。
- 前置条件：
  - 一个**域名**（备案用，几块钱/年的即可）
  - 一台**备案服务器**（华为云最低配 ECS 或备案授权码）
- 材料：身份证、人脸核验、App 名称/用途说明、域名证书。
- 注意：
  - 备案主体信息必须与开发者实名信息一致。
  - App 名称、用途描述要与实际上架内容一致，否则会被打回。

## 3. 软件著作权登记

- 办理平台：中国版权保护中心（https://register.ccopyright.com.cn/ ），「计算机软件著作权登记」R11。
- 现在发**电子证书**，正常周期约 15 个工作日，可加急（收费）。
- 需要材料：
  - **源代码文档**：前后各连续 30 页（共 60 页），每页约 50 行，页眉标注软件名称 + 版本号。本项目可直接从 `harmonyos/entry/src/main/ets/` 导出生成。
  - **操作说明书/设计说明书**：含截图、功能说明，十几页即可。
  - 申请表（在线填写）。
- 软件名称建议：「发来文件传输软件 V1.0」之类，名称要与开发者信息一致。

## 4. 发布签名与 release 出包

> ⚠️ 当前 `harmonyos/build-profile.json5` 挂的是**调试证书**（`C:\Users\jht\.ohos\config\` 下自动生成的 debug 签名），**只能用于开发调试，不能上架**。上架必须用 AGC 签发的发布证书。

### 4.1 在 AGC 创建应用

1. AGC → 我的应用 → 新建应用 → 选择「HarmonyOS 应用」。
2. **包名（bundleName）必须填 `com.falai.transfer`**（与 `harmonyos/AppScope/app.json5` 一致）。
3. ⚠️ bundleName **上架后不可修改**，确认无误再创建。

### 4.2 生成发布密钥与 CSR

DevEco Studio → Build → Generate Key and CSR：

1. 生成私钥库 `.p12`（自设密码，**妥善保管，丢了无法更新 App**）。
2. 用 `.p12` 生成 CSR 文件 `.csr`。

### 4.3 申请发布证书与 Profile

1. AGC → 用户与访问 → 证书管理 → 新增证书：上传 CSR，下载**发布证书** `.cer`。
2. AGC → 我的项目/应用 → HarmonyOS 应用 → HAP Provision Profile 管理 → 新建**发布 Profile**：选择应用 + 发布证书，下载 `.p7b`。

### 4.4 配置 release 签名

在 `harmonyos/build-profile.json5` 的 `app.signingConfigs` 中**追加**（保留现有 default 调试配置）：

```json5
{
  "name": "release",
  "type": "HarmonyOS",
  "material": {
    "certpath": "<发布证书 .cer 路径>",
    "keyAlias": "<创建密钥时的别名>",
    "keyPassword": "<密钥密码>",
    "profile": "<发布 Profile .p7b 路径>",
    "signAlg": "SHA256withECDSA",
    "storeFile": "<发布密钥 .p12 路径>",
    "storePassword": "<密钥库密码>"
  }
}
```

并将 products.default 的 `signingConfig` 改为 `"release"`（或单独建一个 release product）。

> 密码安全提示：`keyPassword`/`storePassword` 是明文或加密串写在工程里，**不要把含真实发布密码的 build-profile.json5 提交到公开仓库**。可用 DevEco 的密码加密功能或本地覆盖文件。

### 4.5 命令行出 release 包（本机已验证的构建方式）

Git Bash 下：

```bash
cd /e/mobileApp/file-transfer/harmonyos
export DEVECO_SDK_HOME="E:\\DevEco Studio\\sdk"
"/e/DevEco Studio/tools/node/node.exe" "/e/DevEco Studio/tools/hvigor/bin/hvigorw.js" \
  --mode module -p product=default assembleApp --no-daemon
```

产物：`harmonyos/entry/build/default/outputs/default/entry-default-signed.app`（上架传 `.app` 包；DevEco 图形界面则 Build → Build App(s)）。

## 5. AGC 后台资料与提交审核

### 5.1 应用信息

- 应用名称、图标（1024×1024）、分类（建议：实用工具）。
- 简介 + 详细介绍（说明：局域网内安卓/鸿蒙/PC 互传文件）。
- 截图：手机 3~5 张（真机截图即可）。

### 5.2 隐私政策（审核必查）

- **必须有公网可访问的 URL**（GitHub Pages、Gitee Pages 均可）。
- 内容要点：收集哪些信息（本 App 应声明不收集个人信息）、使用的权限及用途、联系方式。
- 本项目涉及的权限及用途说明（已与 `harmonyos/entry/src/main/module.json5` 实际声明核对，审核时同步填写）：

| 权限 | 用途说明 |
|---|---|
| `ohos.permission.INTERNET` | 局域网内建立 TCP/UDP 连接，发现设备并传输文件 |
| `ohos.permission.GET_WIFI_INFO` | 获取当前 WiFi 信息用于局域网设备发现 |
| `ohos.permission.GET_NETWORK_INFO` | 判断网络状态，保证传输在局域网环境下进行 |
| `ohos.permission.WRITE_IMAGEVIDEO` | 将接收到的图片/视频保存到系统相册（运行时弹窗申请） |
| `ohos.permission.DETECT_GESTURE` | 页面手势交互 |

> 提示：权限越少越好过审。`DETECT_GESTURE` 若界面未实际用到，建议上架前从 `module.json5` 移除。

### 5.3 提交审核

1. 上传 `.app` 包，填版本信息（versionName 1.0 / versionCode 1）。
2. 填备案号、上传软著证书。
3. 提交，审核周期约 1~3 个工作日；被打回按意见改完重提即可。

## 7. 上架后维护须知

- **版本更新**：versionCode 每次递增，用**同一把发布密钥**签名（密钥丢失 = 无法更新，只能换包名重新上架）。
- 备案信息变更（名称、主体等）需在接入商处变更备案。
- 软著证书、密钥 `.p12`、证书 `.cer`、Profile `.p7b` 建议统一归档备份。
